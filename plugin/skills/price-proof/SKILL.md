# Price Proof

Stress-test your price before you quote it. Runs a structured ANALYZE → PLAN → COUNTERCHECK → TEST → ACT sequence on any pricing decision — retainers, project fees, hourly rates, service packages.

## When to Use

- "I'm about to quote a client and want to check my price"
- "Does this rate make sense for this type of engagement?"
- "Help me stress-test my pricing before the meeting"
- "I'm not sure if I'm too high, too low, or just right"
- Invoked as Step 1 of the Before the Meeting bundle

## What You Need Before Starting

- **Scope of work**: what the engagement covers (deliverables, duration, effort)
- **Client type**: company size, sector, budget signals you've observed
- **Your rate idea**: the number you have in mind (or a range)
- **Market context** (optional): comparable rates you've seen, what competitors charge, what the client has mentioned

If any of these are missing, ask before proceeding. Do not guess the scope or client context.

## Workflow

1. **ANALYZE** — Map the pricing context
   - Extract: scope, effort level, client type, market segment, your cost base (time + overhead)
   - Identify: what value does the client receive? What problem are you solving?
   - Flag: any signals that suggest price sensitivity (startup vs. enterprise, fixed budget, procurement process)

2. **PLAN** — Build the pricing model
   - Set anchor, floor, and ceiling based on scope and client type
   - Map the price to the value delivered — not just time spent
   - Identify the pricing format that fits the engagement (fixed fee, retainer, day rate, milestone-based)

3. **COUNTERCHECK** — Challenge the model
   - What assumptions were made without evidence?
   - What happens if a competitor undercuts by 20%?
   - Where does the price justify itself and where does it break?
   - Is the format right for how this client buys? (e.g., monthly retainer vs. annual contract vs. project fee)
   - What are the 3 most likely objections to this price?

4. **TEST** — Run 3 rate scenarios
   - Low scenario: minimum viable rate — what happens to perceived value and margin?
   - Mid scenario: your target rate — how does it hold against likely objections?
   - High scenario: stretch rate — what justification is needed, what is the walk-away risk?

5. **ACT** — Deliver the verdict
   - Recommended rate with rationale the user can defend in the meeting
   - go / adjust / hold verdict
   - Top 3 objections to anticipate + one-line response for each
   - One reframe that strengthens the value case if price is challenged

## Output

- Pricing model (anchor / floor / ceiling)
- Competitive stress-test summary
- 3 rate scenarios with risk assessment
- Top 3 objections + responses
- go / adjust / hold verdict with recommended rate

## Constraints

- Never suggest a rate without grounding it in the scope and client context provided
- Never skip the COUNTERCHECK step — this is the differentiator
- If scope is unclear, ask before building the model
- Do not assume the client's budget — use signals the user provides

## Common Mistakes

| Mistake | Fix |
|---|---|
| Jumping to a number without mapping the scope | Complete ANALYZE before building the model |
| Skipping the competitor undercut scenario | Always run the 20% undercut test in COUNTERCHECK |
| Presenting only the recommended rate | Always show all 3 scenarios so the user understands the range |
| Ignoring the pricing format | The format (retainer / fixed fee / day rate) matters as much as the number |
