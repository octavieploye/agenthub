# Phase 5: Conversion Review
# Agent: conversion-reviewer | Input: Phase 2 + Phase 3 + Phase 4 | Output: Conversion Review Report

## Purpose

Stress-test all output from Phases 3 and 4 against established conversion frameworks. Identify what passes, what fails, and what blocks conversion. Do NOT rewrite — flag precisely so landing-copywriter or content-builder can fix.

---

## Section A: Hero — 4-Second Test

Read the hero section aloud. Time it.

- [ ] **Kicker:** Shows traction (users / reviews / stat) — NOT a descriptor
- [ ] **Headline:** Simple words — zero jargon. Both problem AND solution clear within 4 seconds
- [ ] **Subheadline:** Explains HOW without repeating the headline
- [ ] **CTA button:** Connects directly to headline message. Not "Sign Up" / "Get Started" / "Learn More"
- [ ] **Visual brief:** Written AFTER headline. Visual shows problem→solution connection (not aesthetic-first graphic)
- [ ] **Validation row:** Specific numbers or external logos — not generic trust badges

Fail format: `[FLAG A1: kicker is a descriptor — should show traction: "[specific direction]"]`

---

## Section B: Doubt-Clearing Completeness

For each doubt-clearing section:

- [ ] Section answers a specific dependency from the Phase 2 dependencies list
- [ ] Section has a CTA repetition immediately after it
- [ ] Social proof: each testimonial direction is specific (buyer type + outcome + timeframe)
- [ ] Use case map: buyer can see themselves in at least one category
- [ ] Credibility block: contains ONE specific stat or study (not just a bio)
- [ ] Dependencies list from Phase 2 is fully covered — flag any unanswered dependency
- [ ] FAQ has "ask a question" mechanism

Fail format: `[FLAG B3: dependency "requires existing email list" not addressed in any section — add doubt-clearing section]`

---

## Section C: Pricing / Assessment Hook

**Pricing (if present):**
- [ ] Plan C costs ≥3× Plan B (anchor functional)
- [ ] Plan A is genuinely low-friction (not just cheap)
- [ ] Plan B marked as recommended with visual emphasis

**Assessment hook (if present):**
- [ ] Hook is ONE type only: frustration OR results (not blended)
- [ ] CTA emphasizes: free + fast (3 minutes) + immediate recommendation
- [ ] Dynamic results page maps 3 lead tiers to 3 distinct next steps
- [ ] Frustration hook uses verbatim buyer language from Phase 1

Fail format: `[FLAG C1: Plan C ($49) is only 1.6× Plan B ($29) — insufficient anchor; Plan C should be ≥$87]`

---

## Section D: Final CTA

- [ ] Final CTA does NOT repeat the top headline
- [ ] Final CTA references proof points from earlier on the page
- [ ] Final CTA benefit-rich (uses Phase 2 key benefits explicitly)
- [ ] Social links present as credibility signals (not decoration)
- [ ] What happens immediately after clicking is stated

Fail format: `[FLAG D1: final CTA repeats hero headline — rewrite with benefit summary from proof sections]`

---

## Section E: Strategy Alignment

- [ ] All copy uses verbatim buyer language from Phase 1 — no invented phrases
- [ ] No product claims appear that are not in Phase 0 or Phase 2
- [ ] One-sentence brand pitch from Phase 2 is traceable in the headline
- [ ] Copy urgency level matches product classification:
  - Penicillin: urgency + fast time-to-value language present
  - Morphine: trust + credibility + long-term social proof present
  - Vitamin: desire + aspiration + social validation present

Fail format: `[FLAG E2: headline uses penicillin urgency framing but product is classified as vitamin — realign or reclassify]`

---

## Section F: Content / Articles

For each article:
- [ ] Leads with pain, not product
- [ ] First paragraph uses verbatim buyer language (sourced from Phase 1)
- [ ] Product not mentioned until soft CTA at close
- [ ] Soft CTA is a helpful next step, not a sales pitch
- [ ] Article angle matches one of: frustration / diagnostic / readiness (not blended)

For onboarding copy:
- [ ] Welcome screen shows product in action — not a feature list or promise
- [ ] Personalization questions visibly change what user sees next
- [ ] Outcome framing is specific (timeframe + specific outcome — not "improve your X")
- [ ] Pre-permission screen present before any notification request
- [ ] Checklist items written as outcomes, not actions

---

## Readiness Assessment

**Ready:** All A–F sections pass or have only minor copy refinements needed
**Needs Revision:** 1–3 significant flags; specific sections need rewriting before launch
**Blocked (structural issue):** A fundamental positioning, segment, or differentiation problem exists that copy cannot fix — return to Phase 2 or flag to user

If Blocked: name the specific structural issue and which phase it originates from.

---

## Output: Conversion Review Report

1. Section-by-section checklist (pass / fail / flag per item)
2. All flags formatted: `[FLAG {section}{number}: what is wrong → specific replacement direction]`
3. Top 3 highest-impact improvements ordered by estimated conversion lift
4. Overall readiness score: **Ready / Needs Revision / Blocked**
5. If Blocked: structural problem description + upstream phase to revisit
