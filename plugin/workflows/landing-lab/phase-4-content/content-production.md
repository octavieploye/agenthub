# Phase 4: Content Production
# Agent: content-builder | Input: Phase 1 + Phase 2 + Phase 3 | Output: Content Package

## Purpose

Produce pain-oriented articles, onboarding copy, and supporting content. All content is downstream from the approved VP and uses verbatim buyer language from Phase 1. Nothing is invented.

---

## Articles: Pain-Oriented (3 articles, one per pain angle)

### Selection Rule

Each article addresses ONE blatant pain from the Phase 1 Pain Mapping Report. Select pains that:
- Score Strong on Urgency (U3) or Unworkable (U1) in the Four U's table
- Map to the top segment's Before state
- Connect naturally to the product's After state

### Article Structure

1. **Hook** — open with the pain in the buyer's own verbatim language (cited from Phase 1)
2. **Problem depth** — why this keeps happening despite the buyer's best efforts
3. **Stakes** — concrete cost of inaction (time / money / risk / missed outcome)
4. **Solution frame** — the category-level shift needed (NOT a product pitch)
5. **Soft CTA** — "If this resonates, [product name] addresses exactly this. [landing page link]"

### Length
600–900 words. Enough to establish authority; short enough to keep attention.

### Angle Selection (one per article, never repeat)

| Angle | Title pattern | Best for |
|---|---|---|
| Frustration | "Why [pain] keeps happening despite [common attempt]" | Unworkable / Urgent pains |
| Diagnostic | "The [N] signs you're [problem] — and what to do" | Underserved segment identification |
| Readiness | "What [desired outcome] actually takes in [year]" | Results hook, aspirational buyers |

### Language Rules

- Use verbatim buyer phrases from Phase 1 (cited)
- Never invent pain language — if no sourced phrase exists, note `[PARAPHRASE — source needed]`
- Never name the product until the soft CTA
- Never list features — describe the outcome category only

## Onboarding Copy (if product has onboarding flow)

### Welcome Screen
Show product in action. NOT a feature list. NOT a promise. Direct demonstration.
Copy direction: `[VISUAL NEEDED: product in action state]`
Copy line: "[What the user sees happening]" — not "Welcome to [Product]"

### Personalization Block (2–3 questions max)

Each question must:
- Visibly change what the user sees next (not just stored for later)
- Be answerable in one click / one selection (not free text)

After answers:
- Transition screen: "Your personalized [plan / dashboard / recommendations] is being built..."
- Show what was unlocked: "Based on your answers: [specific thing that changed]"

### Outcome Framing

After personalization:
- Tell buyer what they will achieve and when: "In [timeframe] you'll be able to [specific outcome from Phase 1 After state]"
- Show a simple progress graph or indicator if applicable

### Progress Indicators

Every screen must show progress. Never let the user feel the flow is endless.
Format: "Step 2 of 5" or progress bar — choose one, apply consistently.

### Aha Moment Bridge

Define the aha moment for this product (from Phase 0 product core + Phase 1 After state).
Write the bridge copy for the screen immediately before it:
"You're one step from [specific first win that represents aha moment]."

### Pre-Permission Screen (before OS notification request)

Write a custom screen that explains WHY notifications help the user:
> "I'll remind you to [specific use case] so [specific benefit] becomes automatic — not something you have to remember."

Then show the OS permission dialog. Never show dialog without this primer.

### Onboarding Checklist (replaces popups and guided tours)

4–6 steps written as outcomes the user achieves, not actions they take:
- NOT: "Set up your profile"
- YES: "Your profile is ready — [product] now shows you [personalized thing]"

Checklist persists after dismissal of any initial onboarding modal.

## Founder / About Us Note (if requested)

Format: personal note from founder, not a corporate bio.

Structure:
1. One specific origin moment: why does this product exist? (what happened to the founder?)
2. The specific problem they set out to solve (matches Phase 1 pain framing)
3. One sentence on what they believe that the market hasn't caught up to yet
4. Sign-off: personal name + `[VISUAL NEEDED: handwritten-style signature]`

Max 150 words. Read as a note from a person, not a press release.
