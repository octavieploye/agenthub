## PURPOSE

Frameworks for structuring days, weeks, and months. These are the tactical
tools that turn constraints, priorities, and energy rules into an actual schedule.

---

## FRAMEWORK 1 — DAY THEMING

Assign each day a primary role to eliminate daily "what should I work on?" decisions.

### Example week:

| Day | Theme | Task types |
|---|---|---|
| Monday | Strategy & planning | Weekly review, goal setting, project planning, IPAs |
| Tuesday | Building / making | Deep work, coding, writing, product development |
| Wednesday | Content | Recording, editing, writing, content creation pipeline |
| Thursday | People & operations | Meetings, team 1:1s, client calls, admin |
| Friday | Finishing & review | Wrap up loose ends, weekly review, next week prep |

### Rules:
1. One theme per day — not two
2. Theme aligns with energy patterns (heavy creative = early in week)
3. Manager days cluster all meetings onto 1-2 days
4. Maker days are meeting-free
5. If a task does not match today's theme, it waits (unless critical-path)

### Variations:
- Half-day theming: morning = maker theme, afternoon = manager theme
- Project theming: Monday = Project A, Wednesday = Project B
- Role theming: Tuesday = CEO hat, Thursday = developer hat

## FRAMEWORK 2 — TIME BLOCKING

Every hour of the workday has a purpose. No unassigned time.

### How to build a time-blocked day:

```
1. Start with sanity anchors (already subtracted — see human-constraints.md)
2. Place maker blocks in peak energy window (2-3 blocks of 90 min)
3. Place manager blocks in declining energy window
4. Place admin/email in low energy window
5. Add transition buffers (10-15 min) between different task types
6. Add one "flex block" (30-60 min) for overflow and surprises
7. End with shutdown ritual (15-20 min)
```

### Time boxing rules (Parkinson's Law):
- Set a fixed duration BEFORE starting — work expands to fill available time
- When the box ends, stop — even if not "perfect"
- Better to produce 80% quality in the box than 100% quality with no time limit
- Short boxes (25-45 min) for routine tasks
- Long boxes (90 min) for deep work — aligned with ultradian cycles

## FRAMEWORK 3 — 3-3-3 METHOD (Burkeman)

Simple daily structure when full time blocking feels heavy.

| Block | What | Duration |
|---|---|---|
| 3 hours | Deep work on ONE important project | Morning peak energy |
| 3 tasks | Medium-priority tasks (30-60 min each) | Mid-day |
| 3 small things | Quick tasks under 15 min each | End of day |

### Rules:
1. The 3-hour block is ALWAYS the first block of the day
2. The ONE project is chosen the night before (shutdown ritual)
3. Medium tasks are pre-selected — no deciding in the moment
4. Small things are batched — do all three back-to-back

## FRAMEWORK 4 — TASK BATCHING

Group similar tasks into a single block to minimize context switching.

| Batch type | Tasks grouped | When |
|---|---|---|
| Communication batch | All emails, all Slack, all messages | 2-3 fixed times per day (e.g., 11am, 3pm, 5pm) |
| Meeting batch | All meetings back-to-back | Manager block or manager day |
| Creative batch | All writing, all recording, all design | Maker block |
| Admin batch | Invoicing, bookkeeping, file organization | Friday afternoon or low-energy slot |
| Review batch | All code reviews, all content reviews | One block, not sprinkled through day |

### Rules:
1. NEVER check email/Slack outside of communication batches
2. Batch minimum = 3 similar tasks — below that, just do them individually
3. Set expectations with others: "I respond to messages at 11am and 3pm"
4. Batching across projects is powerful: all marketing for all projects in one block

## FRAMEWORK 5 — WEEKLY REVIEW (GTD)

David Allen: "The critical success factor for the whole system."
A task list you do not review stops being trusted.
A list you do not trust is one you ignore.

### When: Friday afternoon or Sunday evening — 20-60 minutes

### The checklist:

```
1. COLLECT — Empty all inboxes (email, notes, messages, mental)
   → Every open loop captured in one trusted system

2. REVIEW — Look at every active project and task
   → Is it still relevant?
   → Is it blocked? By what?
   → Is it on track for its deadline?

3. ASSESS — Check the week that just ended
   → What got done? What didn't?
   → Why didn't it get done? (capacity? priority? avoidance?)
   → Any tasks that should be re-triaged? (human→AI, outsource, delete)

4. PLAN — Set up next week
   → What are the 3 most important outcomes for next week?
   → Which project's critical-path tasks must happen?
   → Place maker blocks first, then manager blocks
   → Check for conflicts with user exceptions

5. CALIBRATE — Adjust estimates
   → Did tasks take longer than estimated? Update the baseline.
   → Is one project starving? Rebalance.
```

## FRAMEWORK 6 — SHUTDOWN RITUAL

End-of-day ritual that creates a clean break between work and personal time.

### When: Last 15-20 minutes of each workday

### The sequence:

```
1. CAPTURE — Review all inboxes, notes, and messages
   → Every incomplete task recorded in trusted system
   → Nothing left open in your head

2. REVIEW — Check tomorrow's calendar
   → Any conflicts?
   → Any prep needed?
   → Is the first maker block protected?

3. PLAN — Set tomorrow's #1 task
   → The ONE thing you will start with in the morning
   → This eliminates the "what should I do?" decision at 8am

4. CLOSE — Say "shutdown complete" (or equivalent trigger phrase)
   → Close all work apps
   → Do not reopen until morning
   → If a thought pops up, write it down and let it go
```

### Why this matters:
- Prevents rumination on unfinished work during personal time
- The Zeigarnik Effect: open loops stay in memory — shutdown closes them
- Captured tasks in a trusted system = brain can let go
- Planning tomorrow removes decision fatigue from the morning

## FRAMEWORK 7 — STARTUP RITUAL

Morning ritual to enter the workday with intention, not reaction.

### When: First 15-30 minutes of workday (BEFORE opening email/chat)

### The sequence:

```
1. REVIEW — Check today's plan (set during last night's shutdown)
   → What is the #1 task?
   → What are the time blocks?

2. PREPARE — Set up the workspace for the first maker block
   → Close all irrelevant apps and tabs
   → Open only what is needed for the #1 task
   → Put phone on DND

3. START — Begin the #1 task immediately
   → Do NOT check email first
   → Do NOT check Slack first
   → Do NOT scroll news first
   → The first 90 minutes are sacred
```

## MONTHLY CADENCE

| Week position | Focus |
|---|---|
| Week 1 | Execute — head down on current projects |
| Week 2 | Execute — continue momentum |
| Week 3 | Review — monthly review of all projects, rebalance capacity |
| Week 4 | Plan — set next month's priorities, update project calendars |

### Monthly review (60-90 min):
1. Which projects moved forward? Which stalled?
2. Are priorities still correct? (Re-run prioritization-rules.md)
3. Are time estimates accurate? (Calibrate from actuals)
4. Is any project starving? (Rebalance weekly allocation)
5. What should be stopped, started, or continued?

---

## ANTI-PATTERNS

1. No weekly review — the system decays within 2 weeks
2. No shutdown ritual — work bleeds into personal time, recovery suffers
3. Checking email first thing in the morning — gives away your peak energy to other people's priorities
4. Day theming with exceptions every day — defeats the purpose
5. Time blocking every minute — no flex block means no room for reality
6. Batching communication but leaving notifications on — the ping breaks focus even if you don't respond
7. Never recalibrating time estimates — repeating the same optimism bias
8. Skipping the monthly review — projects drift without course correction
