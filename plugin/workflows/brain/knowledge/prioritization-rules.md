# KNOWLEDGE: Task Prioritization Rules

UPDATED: 2026-06-25
SOURCE: Business research — [source], Graham, Koe, MoSCoW, Eisenhower, IPA framework, critical path method

## PURPOSE

Rules for deciding what task to work on first. Apply these rules in order.
When two tasks compete for the same time slot, the task matching the
highest-numbered rule wins.

---

## RULE 1 — REVENUE FIRST (IPA)

Income Producing Activities come before everything else.

| IPA examples | NOT IPA |
|---|---|
| Sales calls | Redesigning logo |
| Client deliverables | Organizing files |
| Sending invoices | Reading articles |
| Lead generation | Internal meetings with no decision |
| Product launches | Perfecting tools/setup |

Do IPAs first. Score every task 1-10 on revenue impact.
Tasks below 5/10: delegate, automate, or delete.

One hour of high-leverage work can produce more value than ten hours of
low-leverage busywork.

---

## RULE 2 — BOTTLENECK FIRST (Theory of Constraints)

Every business has ONE primary factor limiting growth at any given time.

Before starting work, ask three questions:
1. What problem, if solved, would make all other problems smaller?
2. What am I hoping to accomplish?
3. Is this worth doing at all?

Find the constraint. Focus there. Eliminate or postpone everything else
until the constraint is resolved.

---

## RULE 3 — BLOCKING TASKS FIRST (Critical Path)

If Task B cannot start until Task A is done, Task A is a blocking task.
Blocking tasks come before non-blocking tasks.

The critical path is the longest chain of dependent tasks. If any task on
the critical path slips, the entire project slips by the same amount.

Dependency types (most common first):
1. Finish-to-Start — A must finish before B can start
2. Start-to-Start — A must start before B can start
3. Finish-to-Finish — A must finish before B can finish
4. Start-to-Finish — A must start before B can finish

Rule: always identify what is blocking other work and do that first.

---

## RULE 4 — MUST BEFORE SHOULD (MoSCoW)

Categorize every task into one of four buckets:

| Category | Effort budget | Definition |
|---|---|---|
| MUST have | 50-60% | Non-negotiable. Project fails without it. |
| SHOULD have | 10-20% | High value but project survives without it. |
| COULD have | ~20% | Nice-to-have. First to cut if time is tight. |
| WONT have | 0% | Explicitly agreed as not now. |

If the timeline is threatened, cut COULD first, then SHOULD.
MUST items never exceed 60% of total effort — exceeding this signals
the scope is too large.

---

## RULE 5 — IMPORTANT BEFORE URGENT (Eisenhower + Energy)

| | URGENT | NOT URGENT |
|---|---|---|
| **IMPORTANT** | Do now — but do not let it consume the whole day | Schedule in peak energy blocks (maker time). This is where growth happens. |
| **NOT IMPORTANT** | Delegate or batch into manager blocks | Delete. Do not do this. |

Most "urgent" tasks do not grow the business.
The highest-value quadrant is IMPORTANT + NOT URGENT — maker work,
strategy, system building. This is the quadrant most people neglect.

Match quadrant to energy:
- Peak energy (morning for most) = Important + Not Urgent (deep work)
- Declining energy (afternoon) = Urgent + Important (reactive decisions)
- Low energy (end of day) = Urgent + Not Important (email, admin batching)

---

## RULE 6 — LEVERAGE HIERARCHY

When multiple tasks pass Rules 1-5, rank by what compounds:

| Priority | Task type | Why it comes first |
|---|---|---|
| 1 | Revenue generation | Keeps the business alive today |
| 2 | System building | Do once, benefit forever — creates leverage |
| 3 | Customer acquisition | Pipeline for future revenue |
| 4 | Strategic decisions | Wrong direction wastes everything downstream |
| 5 | Relationship building | Compounds over time but rarely urgent |
| 6 | Admin / maintenance | Necessary but never first |

---

## RULE 7 — FOCUS BEATS HOURS

Less time with more focus always beats more time scattered.

| Scenario | Output |
|---|---|
| 4 hours focused | Higher results |
| 12 hours scattered | Lower results |

For builders with a day job (the "5-to-9" after the 9-to-5):
- 1 hour focused on weekdays
- 4+ hours focused on weekends
- Consistency compounds. Volume without focus does not.

## QUICK DECISION TREE

When a new task appears, run this sequence:

```
1. Does it produce revenue directly?
   YES → Do it now (Rule 1)
   NO  → continue

2. Is it the current bottleneck?
   YES → Do it now (Rule 2)
   NO  → continue

3. Is it blocking other tasks?
   YES → Do it before what it blocks (Rule 3)
   NO  → continue

4. Is it a MUST?
   YES → Schedule in current cycle (Rule 4)
   NO  → continue

5. Is it IMPORTANT but not urgent?
   YES → Schedule in next maker block (Rule 5)
   NO  → continue

6. Does it compound over time?
   YES → Schedule this week (Rule 6)
   NO  → Delegate, automate, or delete
```

---

## ANTI-PATTERNS

These mistakes cause solopreneurs to stall:

1. Doing admin first because it "feels productive" — it is not.
2. Treating all urgent tasks as important — most are not.
3. Working on COULD-have items before MUST-have items are done.
4. Ignoring the bottleneck and optimizing around it instead.
5. Spending peak energy hours on email and messages.
6. Never auditing recurring tasks — "Do I still need to do this?"
7. Confusing motion with progress — busy is not productive.
