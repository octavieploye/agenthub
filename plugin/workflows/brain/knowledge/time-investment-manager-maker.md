# KNOWLEDGE: Time Investment — Manager vs Maker Schedule
OWNER:  lead-brain + strategy-advisor
UPDATED: 2026-06-26
SOURCE: Paul Graham (2009 essay), [source] (time management framework), Cal Newport (Deep Work)

---

## PURPOSE

Rules for identifying which time investment mode you are in and how to
protect each mode from destruction by the other.

---

## RULE 1 — KNOW YOUR MODE

Every work session is either Manager mode or Maker mode. Never both.

| | MANAGER MODE | MAKER MODE |
|---|---|---|
| Time unit | 15-90 min slots, 20+/day | 3-4 hour blocks, 2-3/day |
| Empty slot means | Lost opportunity — no return earned | The opportunity — this is where returns happen |
| Meeting cost | Low — just coordination to find mutual slot | 10x — destroys the entire block, not just the meeting duration |
| Output | Coordination: decisions, reports, training, persuasion | Creation: code, writing, design, systems, products |
| Day structure | Clear start/end, proportional to meeting count | Fixed start, variable end — "open to goal" |
| Maximally productive | Fully booked calendar | Empty calendar |

---

## RULE 2 — MEETINGS ARE ASYMMETRIC

A manager requesting "5 minutes" trades 1 of their 20+ daily slots.
A maker saying yes loses 1 of their 2-3 daily blocks.

The math:
- 2 blocks/day x 5 days = 10 maker blocks per week
- 1 meeting in a morning block = 10% of weekly deep-work output destroyed
- The meeting doesn't cost its duration — it costs the full block

This is because of the Zeigarnik Effect: scheduled meetings are open loops.
The maker worries before, ruminates after, and cannot enter flow in between.

---

## RULE 3 — COLLISION RULES

When manager mode and maker mode collide:

| Situation | What happens | Rule |
|---|---|---|
| Manager sees empty maker calendar | Thinks "barely working" | Wrong metric — empty = productive for makers |
| Manager checks in on behind maker | Creates vicious cycle — checking prevents the work | Stop checking, extend trust, measure output |
| Maker says no to meeting | Offends the manager | Value the no — it protects company output |
| Maker says yes to meeting | Destroys the morning | Worse outcome — output lost for both |
| Meeting at 2pm | Entire day shot — worry before, rumination after | Schedule maker meetings at day boundaries only |

---

## RULE 4 — PROTECT MAKER TIME

### If you are the maker:
1. Communicate your mode — tell your team how you work
2. If a meeting lands in your maker block, switch the ENTIRE block to manager
   mode and stack as many small meetings as possible
3. Set standard meeting windows (e.g., Monday and Thursday afternoons only)
4. Push non-urgent meetings to those windows

### If you manage makers:
1. Ask: "Can this wait until our set cadence?"
2. A declined meeting = commitment to meaningful output — do not punish it
3. Ask each team member what their ideal productive day looks like
4. Bunch meetings together to free contiguous blocks

### For any team:
1. Tell people when you will be slow to respond — unmet expectations cause anger, not delays
2. Mandated quiet time — team-wide no-meeting, no-chat blocks
3. Trust and output — do not ping people to verify they are working
4. Audit every recurring meeting: "Do I still need this? Can a system handle it?"

---

## RULE 5 — EVOLUTION PATH

Move from V1 to V3 as you gain calendar control.

| Version | Pattern | When to use | How to transition up |
|---|---|---|---|
| V1 | Maker time = nights, weekends, early mornings | Starting out — no control over daytime | Build systems during maker time that free daytime slots |
| V2 | First half maker, second half manager | Growing — some calendar control | Plan day back-to-front (start from 5pm) to keep mornings open |
| V3 | Entire Maker Days (2-4/week) + Manager Days (1-2/week) | Scaled — full calendar sovereignty | Stack all meetings onto 1-2 days, protect the rest completely |

---

## RULE 6 — AI CHANGES THE EQUATION

AI agents operate asynchronously. This is maker-mode infrastructure.

| Task type | Mode | How AI helps |
|---|---|---|
| Setting up agent contexts, reviewing outputs | Maker | Requires flow state — protect this time |
| Standups, reviews, coordination | Manager | Batch these onto manager days |
| Agent execution (running in background) | Neither | Agents work while you do other things |
| Reviewing agent output | Maker or Manager | Quick reviews = manager slot; deep review = maker block |

Spawn agents during maker blocks. Review during transitions.
Let AI handle overnight or during manager blocks.

## QUICK DECISION TREE

When someone asks for your time:

```
1. Am I in maker mode right now?
   YES → Can this wait until my next manager block?
         YES → Push it there
         NO  → Is it truly critical (not just urgent)?
               YES → Take it, but switch entire block to manager mode
               NO  → Decline. Protect the block.
   NO (manager mode) → Take it. This is what manager mode is for.

2. Is this a recurring meeting?
   YES → Does it still produce value?
         YES → Keep it, but schedule at day boundaries
         NO  → Delete it
```

## ANTI-PATTERNS

1. Identifying as "a maker" or "a manager" — you switch modes, you are not one type
2. Accepting a meeting during maker time "because it's only 5 minutes"
3. Scheduling a performance review at 2pm — costs the person the entire day
4. Checking in more when someone falls behind — you are causing the delay
5. Having no standard meeting windows — meetings colonize the entire week
6. Working V1 forever — you must build toward V2, then V3
7. Wanting both absolute control and absolute freedom — pick one
